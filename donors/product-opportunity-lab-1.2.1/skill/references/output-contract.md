# Output contract

The final deliverable should support the decision, not overwhelm with research volume. Use the **shortest output tier that preserves the decision**.

## Output tiers

### Decision Card — default for FAST or focused VALIDATE
- primary next action;
- 3 strongest evidence points;
- strongest counterevidence;
- quality + readiness (if scored);
- one reversal condition;
- one next test/commitment.

### Shortlist — default for DISCOVER / SCAN / COMPARE
- concise candidate table;
- quality and readiness views separately;
- Pareto trade-offs where relevant;
- recommended next discriminating action.

### Diligence Memo — DEEP/high-stakes or explicitly requested
Use the sections below.

## 1. Decision summary
- mode / depth / objective profile / date;
- primary **next action**;
- why it is the best next decision in 3–5 evidence-backed points;
- Opportunity Quality score + pillar ratings;
- Decision Readiness `R0–R4`;
- critical claim evidence profile, e.g. `problem E3 / budget E2 / distribution E1 / ...`;
- one unknown most likely to reverse the decision.

## 2. Founder context
- Execution Edge relevant to this opportunity;
- Distribution/Access Edge separately;
- constraints that materially changed ranking;
- profile assumptions that remain unknown.

## 3. Opportunity portfolio
For top candidates show:
- target actor + job + trigger;
- status quo and current value/resource flow;
- why now or durable demand;
- quality/pillars;
- gate states;
- claim maturity/readiness;
- explicit reason for promotion/rejection; do not imply one scalar universal rank.

If candidates are heterogeneous, show Pareto trade-offs rather than pretending one decimal score settles the choice.

## 4. Winner/focus deep dive
- solution-neutral JTBD/problem;
- strongest supporting evidence;
- strongest counterevidence;
- user/beneficiary/approver/value-resource owner; for commercial opportunities include buyer/budget owner;
- status quo and switching trigger;
- direct/substitute/service/status-quo competition;
- failed/pivoted analogs with causal confidence;
- beachhead economics and sensitivity;
- distribution/procurement path;
- feasibility/trust/data dependencies;
- durability/retention path.

## 5. Falsifiers
List the 2–4 assumptions whose failure would kill or materially pivot the thesis and the evidence that would resolve them.

## 6. Next experiment(s)
Provide 1–3 in priority order. Each needs:
- critical claim;
- hypothesis;
- method;
- metric;
- pass/fail bar;
- cost/time/irreversibility;
- expected decision change.

## 7. Build handoff only when readiness allows

### R3 — experimental build
Only the narrow prototype/concierge needed to learn:
- target claim;
- minimal workflow;
- success/fail instrumentation;
- time/effort ceiling;
- explicit non-goals.

### R4 — production build candidate
- narrow commitment-worthy outcome; for commercial opportunities make it payable;
- target segment and first-adoption route; for commercial opportunities include ICP and first-customer route;
- value hypothesis; for commercial opportunities include price hypothesis;
- MVP scope;
- architecture constraints;
- success/kill metrics;
- unresolved trust/compliance/data risks.

## Sources
Cite/link material current claims. Keep verification/effective dates visible where freshness matters. Private evidence should use local/source references without inventing URLs.

## Adaptive path trace

For STANDARD/DEEP work, include a compact path trace **only when it improves auditability**:
- modules visited;
- modules intentionally skipped, their `SAFE-SKIP | DEFERRED-DEBT | FORBIDDEN-SKIP` class where material, and the decision reason;
- any DEFERRED-DEBT trigger that becomes mandatory before a larger commitment;
- any JUMP/early EXIT that materially shortened the workflow;
- the terminal stop rule (`fatal gate`, `decision stable`, `test beats research`, `strong commitment`, `hold`, `saturation`, or user-request boundary).

Do not turn this into a process diary. One compact line/table is enough. The user needs to know why important diligence was omitted, not every search step performed.
