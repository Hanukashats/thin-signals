## 1. Зачем

Сервис для Платформы ИИ-аналитики Газпромбанка (кейс Газпромбанк.Тех, `sources/1. Газпромбанк.Тех.pdf`): по открытому запросу («перспективные решения в финтехе») найти в открытых источниках **зарождающиеся** технологии, отделить их от зрелых трендов, стандартов, хайпа и шума, и показать ТОП-15 карточек с источниками, уверенностью и объяснением. Плюс — воспроизводимая классификация на размеченном датасете с отчётом Precision/Recall/F1 (≥75–80 %).

## 2. Решение продукта

**Логическая модель** (`docs/METHODOLOGY.md`): явные признаки зарождения F-P01…F-P18, контр-признаки зрелости M01–M06, порядок gates, арифметика уверенности с reason codes. **Неизменяемая LLM из списка ТЗ** извлекает типизированные факты из прочитанных источников и предлагает следующие проверки. **Код** считает решение, уверенность, динамику и переходы. Обучения весов, fine-tuning, sklearn-классификатора нет (ADR-009).

Четыре независимых результата (не одна универсальная оценка):

1. **Зарождение** — появилось ли новое техническое содержание или применение.
2. **Доказанность** — какие утверждения подтверждены, кем и на какую дату.
3. **Динамика** — что изменилось в сопоставимом корпусе или стадии применения.
4. **Возможность** — зачем банку, какое действие имеет смысл проверить.

Процессный VERIFIED исследования ≠ технология перспективна. HOLD / REJECT / watchlist — валидные исходы. Честный недобор до 15 показывается как недобор.

## 3. Границы

| Входит | Не входит |
|---|---|
| Live-поиск вне 100 seed: SearXNG + arXiv/OpenAlex/Crossref/GitHub | Обучение весов / fine-tuning / sklearn |
| Evidence ledger в PostgreSQL + gates P01–P18 + M01–M06 | Neo4j, S3, Procrastinate, Kafka, K8s |
| `ts eval` P/R/F1 в формате организаторов + корпус контрпримеров | Заявление точности без артефактов прогона |
| Streamlit RU UI: список, отчёт, инспектор источников, реестр исключений | React/Refine-стек (только если останется время) |
| Модели из списка ТЗ через LiteLLM alias; `model_id` в каждом ответе | OpenRouter/автовыбор в продуктовой выдаче |
| Reuse сервисов VM101 по URL; laptop-профиль compose | Второй agent daemon; goal.json как SoT |
| Git: SourceCraft канон + зеркало GitHub для сдачи | Секреты в git |

## 4. Акторы исполнения

- **Продукт:** Python harness (state machine) в FastAPI; Hermes — опция для глубокого countersearch через allowlist.
- **Разработка:** Architect → Implementer → Verifier на LivingSet; INTEGRATE обновляет STATUS.
- **Репозиторий:** SourceCraft `shats123/thin-signals` (см. `docs/ops/SOURCECRAFT.md`), зеркало GitHub перед сдачей.

## 5. Данные и честность

- 100 строк XLSX — seed и design set положительных примеров; `dataset_score/trend/rationale` — метаданные, не признаки.
- Официальный датасет организаторов со скрытой разметкой ещё не получен — блокер в STATUS.
- Новые утверждения требуют snapshot + fragment + предметную проверку; ссылка без прочитанного фрагмента ничего не доказывает.
- Первое упоминание в нашем корпусе ≠ первый год существования технологии. Несопоставимые ряды → `null` + причина.

## 6. Эволюция концепта

Major смена границ/осей/правил → `plan_revision` + ADR + обновление этого файла в том же change-set, что и код. Правила скоринга версионируются (`rules-x.y`) и меняются только через повторный eval. Исторические срезы — `docs/lineage/`.
