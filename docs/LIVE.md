# Живой путь (W3, начат 2026-09-23)

Команда:

```bash
ts run --query "запрос" --limit 3
ts run --query "запрос" --extract    # лабораторный режим, OpenRouter ZDR, model_id пишется в карточку
```

Что делает прогон, по шагам: поиск → снимок (если `--snapshot`) → склейка одного и того же события → контрпоиск зрелости → скоринг → решение, пускать ли в отобранный список.

Источники поиска: SearXNG, если задан адрес, плюс arXiv, OpenAlex, Crossref, Europe PMC, DOAJ, HAL, OpenReview, GitHub, гранты NSF, NIH и CORDIS, черновики IETF, испытания ClinicalTrials и отчёты SEC. Жёлтая пресса и форумы в этот список не входят. Патентный Lens и реестр Роспатента пока без открытого ключа не подключены. Ворота ТОП-15 те же: находка сама по себе в список не попадает.

Опциональный GPT Researcher по умолчанию выключен. При включении он работает
только как discovery и не более одного раза на верхнеуровневый прогон: отчёт
игнорируется, каждый URL повторно скачивается с защитой от private/loopback
адресов и только затем может попасть в общий harness. Запрос наследует общий
дедлайн. Лимиты и endpoint входят в fingerprint; заявленная upstream стоимость
выше потолка отбрасывает весь ответ до использования leads. У API v3.7.0 нет
параметра жёсткого денежного лимита до запуска, поэтому предзапусковые границы —
один запрос и таймаут, а cost ceiling является проверкой уже сообщённой суммы.

Повтор того же запроса в том же UTC-окне, при тех же правилах и версии корпуса, читает сохранённый прогон и не ходит в сеть ещё раз.

## Почему список может быть пустым

Это не поломка поиска. В прогоне `photonic inference processor` (2026-09-23) все пять источников ответили, 10 документов. В ТОП-15 не попал ни один: у кандидата нет подтверждённого перехода стадии, политика вернула `WATCHLIST`, недобор 15 честный.

В список слабых сигналов попадает только карточка, у которой одновременно метка `weak_signal` и решение `RANK_ELIGIBLE`. `watchlist` остаётся наблюдением и не становится слабым сигналом из-за позиции на экране. Зрелое, шум и «просто найдено в поиске» уходят в реестр исключений с причиной.

Если пятнадцати прошедших нет, вкладка «Нужно проверить» показывает ближайшие находки этого прогона. У каждой — доля пройденных проверок, ступень остановки и нехватка данных. Это не заполнение основного списка и не вероятность спроса.

## Что уже работает

- Прогон и публичный payload сохраняются в PostgreSQL; `/v1/runs/latest` возвращает последний завершённый результат.
- `checklist-v19` требует текст из положительного канала, валидную ссылку `[n]`, согласованные content/fragment SHA-256 и реально существующий content-addressed blob. Только повторно проверенный primary-фрагмент может остаться `verified`; snippet, отсутствующий/повреждённый snapshot и сохранённый non-primary автоматически ограничиваются `supported`. Контрпоиск может опровергнуть карточку, но не подтвердить её; другой механизм отсекается до порогов, model/provider provenance сохраняется.
- `retrieval-0.4` включает версию и порядок тематического плана в стабильный
  родительский wide-контекст, поэтому незавершённый результат старого плана не
  переиспользуется. Глобальная воронка склеивает одно событие между темами по
  совместным DOI/URL-псевдонимам, включая неполный DOI и повтор URL, и сохраняет
  подтверждённые причины дочерних исключений. Конфликтующие явные DOI остаются
  разными событиями; ответы после абсолютного дедлайна отбрасываются. Public
  refetch использует проверенный IP напрямую (с исходным Host/TLS SNI), поэтому
  повторное DNS-разрешение не может перенаправить запрос в private/loopback;
  наружу выходят только allowlisted метрики.
- `live-w21` собирает документы и события каждой темы в один типизированный
  `technology-candidate-0.1`. Зеркала одной работы считаются один раз по
  DOI/OpenAlex Work/URL. Независимость организаций не выводится из разных доменов: вклад
  `independent_origins` появляется только при явных устойчивых ID лаборатории
  или учреждения; без них статус независимости остаётся `unknown`.
- `openalex-work-0.1` сохраняет только allowlisted роли: стабильные Work/DOI,
  дату, явные ROR-аффилиации, OA-доступ, число ссылок и флаги целостности.
  Сырые строки аффилиаций не публикуются. `is_retracted=false` означает только
  «OpenAlex/Retraction Watch не поставил флаг», а не завершённую проверку
  исправлений и отзывов; `erratum` и `retraction` помечают тип самой записи.
- Закрытый Streamlit UI на `https://tsignal.aispaces.ru` разделяет состояние прогона, метку карточки, факты, гипотезы, проверки и источники.
- API и UI имеют версионированные persistent units в `deploy/systemd/`; инструкции и rollback — `docs/ops/SYSTEMD.md`.

## Чего этот срез ещё не делает

- Не гоняет PDF через Docling и не считает векторы TEI: склейка событий идёт по DOI/URL, с заголовком как fallback при отсутствии обоих.
- Не заполняет все задуманные step/evidence ledger tables для старых прогонов.
- Не заполняет постоянный per-step ledger, хотя общий статус `succeeded | degraded | failed` уже различает полный и частичный отказ поиска.
- Не исправляет немонотонность весов без новой версии правил и eval.

Извлечение идёт в OpenRouter только со списком моделей, у которых включена защита: `zdr=true` и `data_collection=deny` принудительно выставляются после конфигурационных extras. Запрошенная и возвращённая модели проверяются по allowlist, provider — по ZDR registry.

API: `uvicorn ts.api:app --host 127.0.0.1 --port 8095`, затем `POST /v1/runs` с полями `query`, `limit`, `extract`. В ответе статус прогона и метка сигнала лежат отдельно.
