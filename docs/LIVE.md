# Живой путь (W3, начат 2026-09-23)

Команда:

```bash
ts run --query "запрос" --limit 3
ts run --query "запрос" --extract    # лабораторный режим, OpenRouter ZDR, model_id пишется в карточку
```

Что делает прогон, по шагам: поиск → снимок (если `--snapshot`) → склейка одного и того же события → контрпоиск зрелости → скоринг → решение, пускать ли в ТОП-15.

Источники: SearXNG (если задан `TS_SEARXNG_URL`), arXiv, OpenAlex, Crossref, GitHub. EPO и CORDIS намеренно не вызываются.

Повтор того же запроса при тех же правилах не ходит в сеть ещё раз.

## Почему ТОП-15 может быть пустым

Это не поломка поиска. В прогоне `photonic inference processor` (2026-09-23) все пять источников ответили, 10 документов. В ТОП-15 не попал ни один: у кандидата нет подтверждённого перехода стадии, политика вернула `WATCHLIST`, недобор 15 честный.

В ТОП-15 попадает только карточка, у которой одновременно метка `weak_signal` и решение `RANK_ELIGIBLE`. Зрелое, шум и «просто найдено в поиске» уходят в реестр исключений с причиной.

## Чего этот срез ещё не делает

- Не пишет прогон в PostgreSQL (таблица `runs` есть, запись — следующий шаг).
- Не гоняет PDF через Docling и не считает векторы TEI: склейка событий идёт по DOI и заголовку.
- Не рисует UI.
- В режиме `TS_PRODUCT_MODE=true` флаг `--extract` отказывается звать OpenRouter: для сдачи нужен отдельный разрешённый шлюз.
