# Operator UI dusk pass — implementation brief

## Visual tokens

- Canvas `#E5ECEE`
- Side/secondary surface `#D8E5E9`
- Detail surface `#EDF2F2`
- Cards/inputs `#F5F7F6`
- Selected/info `#D3EBED`
- Muted surface `#DCE2DF`
- Border `#B7C4C5`
- Ink `#142226`
- Secondary text `#536367`
- Action teal `#087A84`
- Brand pine `#0B5D52` with white title and mint `#DDEBE4` support text

Typography uses a restrained editorial hierarchy: Georgia-compatible serif for signal titles and the local system sans stack for controls and metadata. No client-side font service is required.

## Layout

The current backend supports a viewer, not a writable analyst decision queue. Therefore this pass keeps the existing Streamlit route and its functions, but reshapes it into a compact operator workbench:

```text
┌ logo · Тонкие сигналы                    LIVE ┐
├ new search / current query panel              ┤
├ run status · signal decision · candidates     ┤
├ TOP/watchlist tabs                             ┤
│ candidate summary → expandable evidence       │
├ collapsed reasoning / sources / exclusions    ┤
└ export                              admin rail ┘
```

On mobile, the status row wraps, card titles remain readable, and large diagnostic lists stay collapsed until requested. The official emblem uses a square source crop both in the green brand band and as the browser favicon, so it stays legible at small sizes without redrawing the mark.

## Product principles

- Dusk, not dark mode: evidence-heavy reading remains light while the canvas is visibly cooler and darker.
- One characteristic element: a thin teal evidence rail on candidate summaries; no decorative dashboard grid.
- Never imply unavailable analyst actions.
- A saved run whose counters contradict its rows is marked incompatible and not auto-presented as current truth.
- Technical detail is available on demand; decision-relevant facts remain first.

## Self-review before build

The original three-pane Figma concept cannot be copied literally because the live product has no persistent analyst actions or selectable queue API. This brief removes those misleading controls and uses progressive disclosure within the existing route. It also avoids generic rounded-card spam: only search/result groups receive surfaces; long diagnostics become labelled disclosures.
