# Готовое задание следующему агенту

Работай с приложенным архивом «Тонкие сигналы». Цель — повторить эксперимент отбора технологий по документированным правилам и оставить воспроизводимые результаты.

По умолчанию сначала выполни режим A, затем подготовь независимый повтор по режиму C в отдельной папке, если доступен поиск в интернете. Если пользователь поручил только пересчёт, ограничься A. Если поиск недоступен, выполни A и явно назови ограничение C; не имитируй новые источники.

1. Прочитай START_HERE.md, PROVENANCE.md, handoff/REQUEST_AND_ASSUMPTIONS.md.
2. Для процесса используй docs/WORKFLOW.md, для точных правил — docs/GATES_AND_RULES.md и research/model.json. Прочитай docs/SCORING.md и docs/RESEARCH_RUNBOOK.md.
3. Не меняй research/. Проверь целостность командой python verify_archive.py.
4. Выполни python reproduce.py. Сохрани результат проверки; отдели воспроизведение вычислений от проверки научных выводов.
5. Для независимого исследования создай новую рабочую папку и run_config.json по шаблону. По умолчанию воспроизводи конфигурацию среза 2026-09-29 и resurrection, минимум 10 лет, академические гранты допустимы. Если пользователь просит актуальный срез, укажи новую дату и сравнивай как обновление.
6. Формируй собственный длинный список, историю барьеров и современные изменения. Сначала собирай доказательства и оценки, затем сравнивай с прежними рангами. Не воспроизводи механически список из 15.
7. Выполни научный, отрицательный, коммерческий и патентный поиск; сохраняй каждый существенный запрос и его ограничения.
8. Используй первичные источники для технических утверждений. Проверяй даты, единицы и границы системы. Не выдавай расчёт за эксперимент, цель гранта за результат, публикационную лицензию за патентное разрешение.
9. Назначь оценки 0–5 с обоснованием каждой оси. Неизвестное — null. Примени обязательные ворота независимо от баллов.
10. Проверь чувствительность; подготовь сравнение с эталоном и отдельный журнал исключений.
11. Выдай полный отчёт, данные, код/версию расчёта, план следующей проверки и архив с контрольными суммами.

Обязательный смысл результата: искать причинную цепочку «старый подход → прежний барьер → изменившееся условие → экспериментальное следствие → узкое применение → доступность». Для новых открытий допускается emergence с иной конфигурацией весов; не смешивай оценки двух потоков без калибровки.

15 — целевое число исследовательских карточек. Если критерии позволяют меньше, сообщи фактическое число. Кандидаты с HOLD могут быть отдельной исследовательской выдачей, но не называются полностью квалифицированными возможностями. Никаких вымышленных нулевых инвестиций или свободных прав.

Не выполняй outreach, сделки, установку расписаний или интеграцию в backend без соответствующего поручения. Не требуются специальные плагины или несколько агентов. Для отсутствующих инструментов используй функционально эквивалентный способ и запиши замену.

Итог для пользователя: что воспроизвелось, что изменилось, почему изменилось, какие условия открыты и какие файлы передаются. Критерии приёмки — docs/ACCEPTANCE.md.

## Короткая версия для вставки в новый чат

Изучи распакованный архив «Тонкие сигналы». Начни со START_HERE.md и handoff/AGENT_PROMPT.md. Проверь целостность, воспроизведи сохранённый расчёт, затем независимо повтори исследовательский workflow в отдельной папке. Сохрани исходный эталон, документируй источники, оценки, ворота, исключения и все расхождения. Не подгоняй результат под исходные 15 технологий и не объявляй неизвестные инвестиции или права отсутствующими.
