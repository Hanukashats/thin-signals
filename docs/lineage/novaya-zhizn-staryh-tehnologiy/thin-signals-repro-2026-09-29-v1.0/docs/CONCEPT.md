# Концепция продукта «Тонкие сигналы»

## Объект обнаружения

Технологическая возможность — причинная связь между научным механизмом, прежним ограничением и новым условием, которая допускает проверяемое прикладное преимущество.

Карточка:
**функция → старый механизм/новое открытие → ограничитель → изменение условий → эксперимент → применение → покупатель → права → сравнительный тест**.

Пример исходного исследования: насос Кнудсена → трудная микрогеометрия → современные MEMS-процессы → интегрированный газоанализатор → предполагаемый модуль переносного прибора. Коммерческие звенья этой цепочки остаются гипотезами.

## Два потока

**Возвращение старого задела (resurrection).** Найти прежний барьер, его документированное происхождение и современное изменение именно этого барьера. Возраст сам по себе не даёт преимущества. Отдельно отмечать непрерывно исследовавшееся направление и действительно остановленный проект.

**Новое открытие (emergence).** История не обязательна. Нужны первичный эксперимент, изменение технической возможности и раннее прикладное следствие. Научные, коммерческие и правовые ворота одинаково обязательны.

## Почему нужен граф зависимостей

Статья связана с механизмом; механизм — с барьером; барьер — с материалом, оборудованием или процессом; они — с патентом, командой, грантом, компанией и рынком. Сигнал может возникнуть в соседней дисциплине: например, появился способ дешёвого изготовления нужной структуры.

Идентификаторы: DOI для публикаций, ORCID для людей, ROR для учреждений, номера/семейства патентов, юридические идентификаторы для компаний. Названия — поисковые признаки, а не надёжные ключи идентичности.

## Ответственность ИИ и кода

ИИ извлекает утверждения, предлагает причинные связи, ищет возражения и обосновывает экспертные оценки. Каждое значимое утверждение сопровождается источником, датой и ограничением.

Код считает баллы, запрещает обход обязательных условий, хранит версии и формирует воспроизводимый результат. Код не превращает модельное предположение в установленный факт. Статусы доступа, исправлений и рыночной проверки пока устанавливает аналитик на основании документов.

## Продуктовая выдача

Отдельные очереди:

- кандидаты для исследования;
- приоритет проверки;
- наблюдение;
- исключённые с причиной и условием возврата;
- полностью квалифицированные возможности.

В каждой строке: что изменилось, доказательство с условиями измерения, ограничение, диапазон балла, открытые ворота, дата проверки и следующий тест. Количество квалифицированных возможностей может быть нулевым.

## Главные ошибки, от которых защищает концепция

- Старая физика автоматически приписывается молодому устройству.
- Теоретический предел эффективности становится «достигнутым показателем».
- Исследовательский грант объявляется инвестиционным раундом.
- Патентный правообладатель отождествляется с действующим бизнесом.
- Лицензия открытой статьи трактуется как разрешение производить устройство.
- Повторение пресс-релиза на пяти сайтах считается пятью воспроизведениями.
- Улучшение отдельного элемента заменяет сравнение полного изделия.
- Публикационная дата, дата загрузки и дата события смешиваются.
- Высокая оценка скрывает неизвестные права или найденного коммерческого разработчика.

## Текущее состояние

Гипотеза методологии и воспроизводимый офлайн расчёт реализованы. Рабочий продукт потребует полного журнала доказательств, регулярных обновлений, нормализации сущностей, ролевой проверки и исторической валидации. Эти компоненты описаны как следующий этап, а не как уже работающий сервис.
