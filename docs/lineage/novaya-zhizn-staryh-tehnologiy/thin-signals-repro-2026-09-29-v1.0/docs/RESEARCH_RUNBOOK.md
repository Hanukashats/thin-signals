# Как повторить исследование с другим агентом

## A. Точный офлайн пересчёт

Из корня: python verify_archive.py, затем python reproduce.py.

Изменений источников, баллов или модели нет. Результат сохраняется в новой папке runs/. Ожидаются 11 успешных тестов, совпадение ranking.json, sensitivity.json, ranking.csv и REPORT.md после нормализации переводов строк. Независимая проверка структуры также подтверждает 15 карточек, 14 решений, 83 источника и 20 коммерческих запросов.

## B. Повторная оценка тех же свидетельств

1. Создать новую рабочую папку вне research/.
2. Сохранить версию конфигурации и копию исходных источников.
3. Прочитать свидетельства и заново оценить оси, не добиваясь прежнего ранга.
4. Разделить расхождения: иной факт; иной вывод из того же факта; иной вес; иное правило допуска.
5. Считать обе версии, сформировать comparison.md.
6. Указать, какие источники недоступны или изменились. Если использованы новые сведения, это уже обновлённый информационный срез.

Для уменьшения влияния исходного ранга сначала оценить данные без чтения ranking.json и матрицы оценок; при полном доступе к архиву настоящая слепота не гарантируется. Строгий сравнительный эксперимент требует от организатора выдать агенту только задание, регламент и источники до фиксации его оценок.

## C. Независимое новое исследование

Зафиксировать дату и бюджет охвата. Бюджет можно измерять числом предметно проверенных направлений, поисковых семейств и временем проверки; его величина не задана первоначальным пользователем. Не приписывать исходному запуску вымышленные ограничения.

Источники:

| Слой | Ресурсы | Назначение |
|---|---|---|
| Наука | Crossref, OpenAlex, Europe PMC, arXiv, сайты издателей | Метаданные, первичные работы, версии и связи |
| История | NASA NTRS, OSTI, университетские архивы, диссертации | Старые стенды, барьеры, пилоты |
| Права | EPO OPS, Lens, национальные реестры, офисы трансфера | Семейства, владельцы и доступность |
| Проекты | CORDIS, SBIR/STTR, государственные грантовые реестры | Финансирование, партнёры, результаты |
| Коммерция | Сайты компаний/инвесторов, регуляторные раскрытия, каталоги лицензий | Продукты, сделки, лицензии, масштабирование |

URL и проверенные в исходном срезе сведения о доступе находятся в sources.json и REPORT.md. Перед новым подключением проверить текущие условия доступа. Не хранить секретные ключи в архиве.

## Шаблоны поиска

Для каждого кандидата выполнить и записать минимум разные поисковые цели:

- История: синонимы + first demonstration / history / pilot / limitation / abandoned.
- Новое изменение: механизм + материал/изготовление + experimental / prototype / measured.
- Контраргумент: mechanism + limitation / stability / degradation / negative result.
- Коммерция: синонимы + company / startup / product / pilot / funding / acquisition.
- Права: автор/учреждение/название + patent / licensing / exclusive / technology transfer.

Это рекомендуемый регламент следующего запуска, а не заявление о сохранении каждого такого запроса в первом. Реально сохранённый исходный журнал содержит 20 коммерческих запросов; прочие запросы полностью не архивировались.

Записывать query, provider, searched_at, cutoff, candidate_id, URLs, краткий результат и ограничения. «Ничего релевантного» сохранять как результат поиска, не как доказательство отсутствия.

## Сборщик

В новой копии research/:
python collect_metadata.py --check-dois --query "Knudsen pump" --rows 3 --until 2026-09-29 --output metadata_new.json

Скрипт получает метаданные DOI из sources.json и ищет в Crossref/Europe PMC. Он не извлекает автоматически все утверждения, не ищет полный рынок и не закрывает ворота. Сохранять ошибки API. 503 не является отсутствием публикаций.

## Источники и даты

Хранить дату события, дату публикации и дату доступа отдельно в новом журнале доказательств. Для каждой важной метрики указать границы системы, условия, единицы и метод. Если есть только аннотация, назвать этот предел. Дата загрузки диссертации не является датой изобретения.

Для исторического повтора среза 2026-09-29 информация, впервые появившаяся позже, не может изменять исходные признаки. При недоступном историческом снимке пометить невозможность доказать, что факт был известен в дату среза.

## Сравнение двух запусков

Сформировать:

- различия конфигурации;
- совпадение и различия состава кандидатов;
- изменения баллов по каждой оси;
- переходы gates/holds/failures;
- ранговую чувствительность;
- новые коммерческие противоречия;
- список источников, которые изменились или не открылись;
- причины каждой замены.

Совпадение ранга не подтверждает научную истину. Расхождение ранга не означает ошибку, пока не разобраны данные и правила.
