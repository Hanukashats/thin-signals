# Ворота и точное поведение прототипа

Текст согласован с сохранённым research/score.py. Оценки и статусы задаются экспертом; код проверяет заявленные значения. Он не выполняет автоматически всю содержательную проверку G0–G6.

## Методологические ворота

| Ворота | Вопрос | Основание прохода |
|---|---|---|
| G0 | Это именно нужная технология и достаточно старый задел? | Идентичность, датировка, связь с историей |
| G1 | Наука пригодна как основание? | Первичный эксперимент, условия, контроль, проверка исправлений |
| G2 | Изменилось ли прежнее ограничение? | Документированная причинная цепочка |
| G3 | Есть ли полезность всей системы? | Сравнение функции с альтернативой |
| G4 | Есть ли свободное окно для выбранной реализации? | Проверка компаний, проектов, лицензий и актуальности |
| G5 | Можно ли получить права, образец и команду? | Документированный доступ |
| G6 | Можно ли выполнить решающий тест? | Согласованный протокол и доступ к выполнению |

## Исключения failures, реализованные кодом

| Флаг | Точное условие |
|---|---|
| future_information | candidate.as_of позже model.as_of |
| missing_sources | source_ids отсутствует или пуст |
| unknown_source_id | ID не найден в реестре |
| future_publication | Известная часть даты published позже соответствующей части даты среза |
| too_young_for_resurrection_profile | Возраст по разности годов меньше minimum_age |
| refuted_or_retracted | retracted равно true ИЛИ science_status равно refuted |
| commercially_occupied | commercial_status входит в exclude_commercial_states |
| rights_unavailable | ip_status равно unavailable |

Коммерческие значения исключения в модели: commercial, scaled, licensed_exclusive, funded_business.

Возраст вычисляется приближённо: год среза минус historical_year. Проверка не считает точные прошедшие дни. В потоке emergence возрастной запрет отключён.

## Удержания holds, реализованные кодом

| Флаг | Точное условие |
|---|---|
| publication_date_needs_review | Непустую дату источника нельзя разобрать как компоненты целых чисел |
| missing_historical_date | В историческом режиме нет целочисленного historical_year |
| commercial_diligence | commercial_status не равен unoccupied_verified |
| rights_diligence | ip_status не равен access_verified |
| source_integrity_screen | retraction_screen не равен screened_no_flag |
| experimental_evidence | evidence неизвестно или меньше 3 |
| historical_fit | В историческом режиме history неизвестно или меньше 3 |
| bottleneck_not_yet_removed | bottleneck неизвестно или меньше 3 |
| incomplete_scores | Есть null в оси с ненулевым весом |
| system_comparison | system_comparison_status не равен validated |
| test_protocol | decisive_test_status не равен agreed |

Один кандидат может иметь несколько удержаний одновременно. Они дедуплицируются. unoccupied_verified означает достаточную документированную проверку для определённой реализации и среза, а не доказательство всемирного отсутствия закрытой сделки.

## Очередь decision

1. Если failures непустой: exclude независимо от балла.
2. Иначе L ≥ 60: priority_diligence.
3. Иначе L ≥ 50: investigate.
4. Иначе: watch.

HOLD не заменяет decision: удержания хранятся рядом. priority_diligence с удержаниями означает приоритет выяснения неизвестного.

Полная квалификация: **fully_qualified = нет failures И нет holds**.

Готовность к обсуждению партнёрского пилота: **partner_review_ready = fully_qualified И L ≥ 70**. Это не автоматическое разрешение на сделку или расходование денег.

## Сортировка и чувствительность

Сначала все не исключённые, затем исключённые. Внутри — убывание L, при равенстве лексикографический ID. Совпавшие баллы не позволяют утверждать качественное превосходство строки выше.

Для каждого из восьми весов коэффициент 0.8 и 1.2; после изменения все веса нормируются до 100. Считаются 16 сценариев и диапазон рангов вместе с базовым сценарием. Совместные изменения весов и неопределённость самих экспертных оценок не моделируются.

## Проверка входных данных

Код отвергает неконечные/отрицательные веса, неверную сумму весов, неизвестный поток, несовпадающий набор осей, булевы/неконечные/выходящие за 0–5 баллы и дубликаты ID кандидатов.

Ограничения версии 0.1, которые нельзя скрывать при повторении:

- Отсутствующая published не создаёт автоматического HOLD. Дату и пригодность источника обязан проверить аналитик.
- Парсер даты проверяет компоненты и порядок, но не весь календарь. Это не полноценный валидатор дат.
- Нет автоматической проверки фактических оснований ручных статусов.
- Само поле science_status, кроме refuted, не доказывает наличие опыта; gate использует также экспертный балл evidence.
- rank() читает sources.json рядом со скриптом, даже если карточки поданы через --candidates.
- --out меняет только путь ranking JSON; CSV и sensitivity записываются рядом со скриптом.
- build_report.py рассчитан на структуру исходной подборки и содержит фиксированные числа/описания. Для нового исследования его текст нужно обновить и проверить.
- Часть тестов зафиксирована на 15 исходных карточках и лидерстве T02. Такие проверки нельзя использовать для навязывания нового результата.

Исходный код оставлен неизменным. Для улучшений создать новую версию и сравнить результат с эталоном.
