# Передача в Cursor / Codex

Цель: реализовать Thin Signals по плану 6.1. Это исследовательский пакет, а не уже запускаемый web-сервис. Не начинать с установки всех исторических скиллов.

## Первые изменения репозитория

1. Прочитать AGENTS.md и текущий код; снять read-only inventory сервисов и версий Agispace-backend. Подтвердить, что можно переиспользовать PG, storage, auth, proxy, LLM gateway, сборщики. Не выводить секреты в отчёт.
2. Добавить CONCEPT/ARCHITECTURE/requirements/plan/ADR и ссылку на этот пакет. У каждого требования state, owner, acceptance и evidence. Перенести требования расширенного ТЗ, не заменяя их историческими заметками.
3. Зафиксировать schema v1: Document/Fragment/Entity/Event/Claim/Edge/Observation/Decision/Run. PG migration, tenant scope и outbox. Написать проверки из PROCESSING_CONTRACT.
4. Импортировать исходные 100 записей как `seed_unverified`, хранить ID и score только как metadata. Применить `dataset_patterns_100` как проектные подсказки. Не отмечать proposed annotations ground truth.
5. Реализовать ingest и один сквозной путь: live запрос → raw snapshot → evidence → candidate → verification → русская карточка. Затем расширять источники и ветки в той же архитектуре.
6. Подключить Hermes через RuntimeAdapter. Зафиксировать allowlist моделей ТЗ, hashes инструкций, ограничения инструментов, timeout/cancel. Если Hermes не проходит acceptance, провести тот же тест OpenCode. Не сравнивать качество по числу скиллов.
7. Добавить PG-vector/FTS и Neo4j projection; блокировать карточку при dangling refs. Восстановить граф из PG как приёмочный сценарий.
8. Подключить Refine/AntD; далее Evidence Inspector, ECharts, Cytoscape и Tiptap. Агент возвращает данные для графиков, не исполняемый пользовательский JavaScript.
9. Собрать независимый eval после freeze правил; сравнить prompt-only/retrieval/full harness. Не выдавать 15 reference unit tests за ML quality score.

## Обязательные сценарии продукта

- Статья, репозиторий и пресс-релиз одного эксперимента дают один event.
- Первое упоминание в нашем 36-месячном корпусе не объявляется первым годом существования технологии.
- Изменённый запрос или неполная выгрузка блокируют численный рост.
- Научный singleton сохранён, даже если не попал в кластер.
- Зрелая родительская тема перенаправлена на проверку новой узкой ветви.
- Future roadmap и инвестиционные переговоры сохраняются, но не увеличивают число действующих внедрений/закрытых раундов.
- Опровержение performance claim не уничтожает связанные, но другие, гипотезы.
- Критический UNKNOWN не превращается в PASS из-за дедлайна.
- Меньше 15 надёжных результатов: показывается честное число и watchlist отдельно.
- После timeout/retry нет повторного event, outbox message или двойной оплаты внутреннего шага.
- Разделение пользователей: inaccessible fragment нельзя процитировать через граф или экспорт.
- Резервная копия восстановлена; новый прогон использует pinned schema/model/skill/source config.

## Конкурсный checklist

Свободное технологическое направление; live-сбор вне 100 seed; ТОП-15 как целевой формат при достаточной базе; мотивация/преимущество/кейс/источники; методика зарождения; проверка зрелости; русские UI и отчёт; карточка источника с названием, URL, датой, типом, языком и ограничениями; PG, Docker, Python; репозиторий и README; доступный стенд; метрики с определённым target.

Неразрешённый пункт: ТЗ просит обучение модели на данных. Ядро работает без fine-tuning; feature classifier предусмотрен отдельно при необходимости. Получить трактовку организаторов и не объявлять соответствие раньше. Шаблон презентации: исходный дизайн обязательных слайдов 7–11 требуется проверить по оригиналу; пакет не содержит подтверждения их окончательной подготовки.

## Границы автоматической эволюции

Новая идея от агента → отдельная issue/ADR → эксперимент → разметка и evaluation → review → pinned release. Код, план и концепт обновляются одним изменением. Зафиксировать проверяемый rollback trigger. Не модифицировать production skill автоматически по единственному удачному ответу.
